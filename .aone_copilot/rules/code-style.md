# Apache RocketMQ 代码风格规范

本项目遵循以下代码风格规范和约定，以确保代码的一致性和可维护性。

## Java 代码风格

1. 缩进：使用4个空格进行缩进，不使用制表符
2. 行宽：每行代码不超过120个字符
3. 括号：使用 K&R 风格，左大括号不换行，右大括号换行
4. 命名：使用驼峰命名法，类名首字母大写，方法名和变量名首字母小写

## 命名约定

1. 类名：使用名词或名词短语，首字母大写，如 `MessageStore`
2. 接口名：使用形容词或名词，首字母大写，如 `MessageProducer`
3. 方法名：使用动词或动词短语，首字母小写，如 `sendMessage`
4. 变量名：使用名词或名词短语，首字母小写，如 `messageCount`
5. 常量名：全部大写，单词间用下划线分隔，如 `MAX_MESSAGE_SIZE`
6. 包名：全部小写，使用点分隔，如 `org.apache.rocketmq.store`

## 注释规范

1. 类注释：每个公共类都应有详细的类注释，说明类的用途和功能
2. 方法注释：每个公共方法都应有详细的 JavaDoc 注释，说明方法的功能、参数和返回值
3. 行内注释：复杂逻辑应有行内注释说明，注释应清晰简洁
4. TODO 注释：标记需要完成或改进的代码，格式为 `// TODO: 说明`

## 代码组织

1. 导入语句：按标准顺序组织导入语句（Java 标准库、第三方库、本项目）
2. 类成员顺序：按以下顺序组织类成员：
   - 静态变量
   - 实例变量
   - 构造函数
   - 公共方法
   - 私有方法
3. 方法顺序：相关方法应放在一起，公共方法在前，私有方法在后

## 异常处理

1. 异常捕获：精确捕获异常，避免捕获通用异常如 `Exception`
2. 异常处理：合理处理异常，避免空的 catch 块
3. 异常抛出：在适当的时候抛出异常，提供有意义的错误信息

## 性能考虑

1. 避免在循环中创建对象
2. 合理使用缓存，避免重复计算
3. 注意资源的释放，如文件句柄、网络连接等
4. 使用 StringBuilder 进行字符串拼接
5. 避免使用同步方法，优先使用局部变量
